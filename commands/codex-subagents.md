# Codex Subagents - 自动安装 + 任务编排（中文版）

你正在通过 MCP 将复杂任务并行委托给多个 Codex 子代理，并协调它们的执行。

> **强制前置条件：** 在进行任何环境检测、环境设置、安装或任务执行前，必须先完整阅读插件仓库根目录的 `AGENT_SETUP.md`，并按其中说明完成环境设置。

## 第 0 步：确保 MCP server 可用（自动安装）

在编排任务之前，先检查工具 `mcp__codex-subagent__spawn_agents_parallel` 是否可用。

### 如果该工具不可用

1. 使用 Bash 或 PowerShell 检测用户的操作系统。
2. 从插件仓库根目录运行对应安装脚本的**自动模式**：

   **Windows（推荐 PowerShell）：**
   ```powershell
   .\install.ps1 -Auto
   ```

   **Windows（旧版 CMD 备用）：**
   ```cmd
   install.bat /auto
   ```

   **macOS / Linux / WSL：**
   ```bash
   ./install.sh --auto
   ```

3. 读取生成的汇总文件：
   ```text
   .codex-subagents-install-summary.json
   ```

4. 根据退出码处理结果：
   - **0**：安装完成。告诉用户：「安装已完成，请完全重启 Claude Code 后再次运行此命令。」然后停止。
   - **1**：安装失败。报告错误并停止。
   - **2**：已安装，但需要用户手动操作（通常是 `codex login` 或重启 Claude Code）。只列出需要用户做的事，然后停止。

### 如果该工具可用

继续执行下面的编排流程。

---

## 第 1 步：任务分析（30 秒）

分析任务，理解：
- 任务范围和边界
- 文件依赖关系
- 最佳并行化策略
- 预期复杂度

## 第 2 步：任务分解（1 分钟）

将任务拆分为可并行执行的原子单元。重要约束：
- 每批最多 3 个代理（避免 MCP 内容溢出）
- 若超过 3 个代理，使用链式分批处理（每批 3 个）
- 使用 TaskCreate / TaskUpdate 跟踪进度
- 将每个代理的工作记录到 `.codex-temp/[时间戳]/[功能名].log`

## 第 3 步：生成 Codex Agent 提示词

为每个子任务创建结构化提示词，包含：
- 具体、原子的任务描述
- 工作目录和相关文件
- 依赖和现有模式
- 功能、测试、风格要求
- 成功标准
- 输出格式

## 第 4 步：设置日志目录

创建日志目录：
```bash
TIMESTAMP=$(date +%Y%m%d_%H%M%S)
LOG_DIR=".codex-temp/${TIMESTAMP}"
mkdir -p "${LOG_DIR}"
```

## 第 5 步：初始化进度跟踪

使用 TaskCreate/TaskUpdate 跟踪批次和每个代理。

## 第 6 步：并行委托 + 链式处理

≤3 个代理时直接并行执行；>3 个代理时分批链式执行。

每批使用 `mcp__codex-subagent__spawn_agents_parallel`，最多 3 个代理。

将每个代理的输出记录到 `.codex-temp/[时间戳]/[代理名].log`。

## 第 7 步：收集和分析结果

每批完成后：
- 提取修改/创建的文件
- 提取测试结果
- 识别错误或警告
- 构建文件变更图以检测冲突

## 第 8 步：应用合并策略

选择合适策略：
- **直接合并**：无冲突
- **顺序集成**：存在依赖关系
- **冲突解决**：存在重叠修改
- **增量验证**：高风险变更

## 第 9 步：质量验证

执行以下关卡：
- 预合并：所有代理完成，无关键错误，路径有效
- 编译：代码可编译/构建
- 静态分析：lint、类型检查、格式化
- 测试：单元、集成、E2E
- 代码质量：无调试语句、正确处理错误

## 第 10 步：生成报告

提供完整报告，包括：
- 摘要（任务、代理数、耗时、状态）
- 批次执行进度
- 代理结果
- 合并摘要
- 验证结果
- 修改文件
- 后续步骤和建议

## 错误处理

**代理执行失败：**
1. 记录失败详情
2. 用优化后的提示词重试一次
3. 若仍失败，标记为需手动完成
4. 继续执行其他代理

**合并冲突：**
1. 创建包含上下文的冲突报告
2. 高亮冲突区域
3. 建议解决策略
4. 请求人工决策

**测试失败：**
1. 识别失败的测试
2. 分析是哪个代理导致的
3. 回滚特定修改
4. 用测试上下文重新运行代理

## 最佳实践

- 将任务拆分为原子、独立的单元
- 每批最多 3 个代理
- 使用 TaskCreate/TaskUpdate 跟踪进度
- 记录所有代理活动
- 增量验证
- 文档化合并决策
- 保留回滚检查点

## 输出语言

始终使用用户偏好的语言进行交流，根据上下文调整回应。
